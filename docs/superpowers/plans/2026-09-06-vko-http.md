# VKO HTTP challenge implementation

Goal: obtain VKO snapshots without Chromium, keeping Renderer as fallback.

Architecture: VkoClient owns an HTTP session's cookies per transport, solves only
its recognised challenge, reads the site's public appConfig and decodes the REST
response. VkoSource maps REST fields to existing snapshots and falls back to HTML
on transport/protocol failures. Empty valid search results are not failures.

Constraints: no new dependencies; bounded retries and pagination; no arbitrary
remote JS execution; retain existing source name and HTML parser; cache for 75 s
and merge simultaneous requests; keep separate cookies for direct and RU proxy.
