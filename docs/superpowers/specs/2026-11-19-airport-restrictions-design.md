# Алерты об ограничениях аэропортов по подпискам — дизайн

**Дата:** 2026-11-19. **Статус:** согласовано с пользователем, ждёт ревью спеки.
**Область:** рейсы с активной подпиской; аэропорты SVO, DME, VKO, ZIA, LED, AER.

## Задача

Для рейса, на который есть подписка, бот должен знать аэропорт вылета и прилёта и
присылать **отдельное сообщение**, когда Росавиация объявляет ограничения в этом
аэропорту или снимает их. Сообщение — сразу после события, в существующем стиле
бота, без дайджестов и отложенных отправок.

Ограничения — временные, из-за БПЛА. Плановые NOTAM-окна и иностранные аэропорты
в эту версию не входят.

## Согласованные решения

| Решение | Значение |
|---|---|
| Аэропорты | SVO, DME, VKO, ZIA, LED, AER |
| Окно рейса | от «вылет − 12 ч» до «прилёт + 2 ч» |
| Режимы | и полное закрытие, и «по согласованию» |
| Тихие часы | 23:00–07:00 МСК, если до рейса больше 6 ч |
| Доставка | сразу, отдельным сообщением; без бэкфилла старых событий |
| Эмодзи | только существующие в проекте; новых не вводим |

## Источник

Единственный оперативный открытый источник — канал «Говорит Росавиация»:

- веб-версия: `https://t.me/s/favt_info` — обычный HTML, 20 постов на страницу,
  назад — `?before=<id>`; авторизация не нужна;
- первоисточник — канал в MAX (в подписи постов «| MAX»); API у MAX нет, веб-версия
  отдаёт пустой SPA, поэтому работаем с Telegram-зеркалом;
- сайт Росавиации (favt.gov.ru) оперативных ограничений не публикует: в новостном
  RSS только пресс-релизы, в открытых данных — ничего по ограничениям.

Формат постов (три шаблона):

```
⛔️ Аэропорты
— ВНУКОВО
— ДОМОДЕДОВО
✈️ВВЕДЕНЫ временные ограничения на прием и выпуск воздушных судов.
```

```
🟡 Аэропорт ДОМОДЕДОВО
принимает и отправляет рейсы по согласованию с соответствующими органами…
```

```
⬜️Аэропорт СОЧИ
✈️СНЯТЫ ограничения на прием и выпуск воздушных судов.
```

Особенности источника, обязательные к учёту:

1. **Reply-цитата.** У поста-снятия в HTML есть `js-message_reply_text` с текстом
   родительского поста. Свой текст поста — только `js-message_text`; иначе парсер
   прочитает цитату и перепутает «введены» и «сняты».
2. **Правки.** Снятие иногда дописывают в тот же пост строкой
   `UPD. Ограничения сняты` / `UPD. Казань открыта`. Поэтому последние две
   страницы перечитываются каждый тик, тексты постов сравниваются по хешу, а при
   изменении поста его события удаляются и пересобираются заново.
3. **Повторы.** «ВВЕДЕНЫ» для того же аэропорта повторяют, пока ограничение
   действует. Повтор не порождает новое уведомление, пока эпизоду меньше 12 ч;
   после — считаем это новым эпизодом.
4. **Пропущенное снятие.** Снятие могут не объявить вовсе. Состояние «закрыт»
   живёт не дольше TTL и не блокирует будущие события.
5. **Сводки.** Посты-сводки («задержаны 103 рейса…») не считаются событием:
   событие только если в первых строках есть шапка «Аэропорт(ы)» и глагол
   «ВВЕДЕНЫ / СНЯТЫ / по согласованию».

## Поведение

### Событие

`closed` — «ВВЕДЕНЫ»; `partial` — «по согласованию»; `lifted` — «СНЯТЫ» или
`UPD` со снятием. Каждое событие привязано к посту (`post_id`), времени поста
(UTC) и списку аэропортов.

### Окно и сторона

- Окно: `[вылет − 12 ч; прилёт + 2 ч]` по текущей оценке (`est or plan`); если
  времени нет — 00:00 МСК даты рейса.
- Аэропорт вылета актуален до `departure.fact`; аэропорт прилёта — до
  `arrival.fact`. В полёте ловим только прилёт.
- Вне окна событие обновляет состояние, но пуша нет. Это и есть «не через неделю»:
  ограничение за неделю до рейса не имеет смысла.

### Сразу

- Каждый тик (120 с) читает ленту; новые события отправляются в том же тике,
  отдельным сообщением на рейс. Никаких очередей, дайджестов и «утренних сводок».
- **Без бэкфилла.** При первом запуске (или пустой базе) максимальный `post_id`
  запоминается как обработанный; старые посты не рассылаются.
- После простоя обрабатываются только посты новее сохранённого `post_id`; события
  старше 30 минут обновляют состояние, но не порождают пуш (чтобы не пришёл
  «введены» двухчасовой давности). Текущее состояние при этом не теряется.

### Ночь

- 23:00–07:00 МСК: пуш подавляется, если до ближайшего значимого времени
  рейса (вылет для аэропорта вылета, прилёт для аэропорта прилёта) больше 6 ч.
- Подавленное событие записывается в `airport_alerts_sent` с признаком
  `suppressed`; «снятие» по нему не отправляется (нечего снимать).
- Утром подавленные события не переигрываются: если ограничение ещё действует,
  оно попадёт в состояние, но отдельного «догоняющего» пуша нет.

### Снятие

- «Снято» отправляется только если по этому эпизоду (аэропорт + `post_id`
  введения) был реальный пуш. Иначе молчим.
- В тексте — длительность: от времени поста о введении до времени поста о снятии.
  Если снятие пришло правкой того же поста (`UPD`), длительность неизвестна —
  хвост «были …» опускаем.

### Дедуп и повторы

- Ключ отправки: `(chat_id, sub_id, iata, episode_post_id, kind)`.
- Повторное «введены» в том же режиме — без пуша; смена `partial → closed` —
  новое сообщение; `closed → partial` — тоже новое (режим смягчился).
- Один пост на несколько аэропортов → одно сообщение на рейс, строки по каждому
  затронутому аэропорту этого рейса.

### TTL

- Для карточки: состояние аэропорта старше 3 ч без подтверждения считается
  неактуальным.
- Для дедупа: повтор «введены» в том же режиме не пушится, пока с последнего
  подтверждения прошло меньше 12 ч. Дольше — новый эпизод (иначе после
  пропущенного «снятия» аэропорт замолчал бы навсегда).

## Сообщения

Заголовок — как у существующих пушей: `route_line(snapshot)`.
Значки — только из общего пака `icons.ic`: `flight-header` (заголовок),
`status-cancelled` (введены ограничения), `status-delay` (по согласованию),
`status-arrived` (сняты). Новых ключей и цветных эмодзи не добавляем; в
примерах ниже — имена значков в фигурных скобках.

Введение ограничений:

```
{flight-header} SU1234 · VKO→AER · 19.11
{status-cancelled} Внуково (VKO): ограничения с 03:12 МСК
Возможна задержка — статус уточняем по табло.
```

«По согласованию»:

```
{flight-header} SU1234 · VKO→AER · 19.11
{status-delay} Внуково (VKO): работает по согласованию с 03:12 МСК
Рейсы выполняются с задержками — следим за статусом.
```

Снятие:

```
{flight-header} SU1234 · VKO→AER · 19.11
{status-arrived} Внуково (VKO): ограничения сняты, были 1 ч 20 мин
```

Аэропорт прилёта — та же строка с уточнением:
`{status-cancelled} Сочи (AER), аэропорт прилёта: ограничения с 04:59 МСК`.

Правила текста:

- название — русское + IATA в скобках: «Внуково (VKO)»;
- время — МСК, `HH:MM`, из времени поста;
- ссылку на пост не вставляем и ведомство в тексте не называем — компактный
  стиль, как у остальных пушей;
- «Возможна задержка» / «Рейсы выполняются с задержками» — обязательная
  оговорка, чтобы не выдавать ограничение за отмену рейса.

## Данные

Миграции в `storage`:

```sql
ALTER TABLE subscriptions ADD COLUMN origin_iata TEXT NOT NULL DEFAULT '';
ALTER TABLE subscriptions ADD COLUMN dest_iata   TEXT NOT NULL DEFAULT '';

CREATE TABLE IF NOT EXISTS airport_posts (
    post_id     INTEGER PRIMARY KEY,
    at          TEXT NOT NULL,          -- ISO, UTC
    text_hash   TEXT NOT NULL,          -- чтобы ловить правки
    reply_to    INTEGER,
    processed_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS airport_events (
    post_id   INTEGER NOT NULL,
    iata      TEXT    NOT NULL,
    kind      TEXT    NOT NULL,         -- closed | partial | lifted
    at        TEXT    NOT NULL,
    episode   INTEGER,                  -- post_id введения, для lifted
    PRIMARY KEY (post_id, iata, kind)
);

CREATE TABLE IF NOT EXISTS airport_state (
    iata       TEXT PRIMARY KEY,
    kind       TEXT NOT NULL,
    since      TEXT NOT NULL,
    post_id    INTEGER NOT NULL,
    updated_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS airport_alerts_sent (
    chat_id    INTEGER NOT NULL,
    sub_id     INTEGER NOT NULL,
    iata       TEXT    NOT NULL,
    post_id    INTEGER NOT NULL,        -- id эпизода = пост введения (не поста снятия)
    kind       TEXT    NOT NULL,        -- closed | partial | lifted | suppressed
    sent_at    TEXT    NOT NULL,
    PRIMARY KEY (chat_id, sub_id, iata, post_id, kind)
);

CREATE TABLE IF NOT EXISTS meta (
    key   TEXT PRIMARY KEY,
    value TEXT NOT NULL
);
```

- `origin_iata`/`dest_iata` заполняются при подписке (из снимка) и обновляются
  в поллере при каждом новом снимке.
- `meta['airport_last_post_id']` — курсор ленты.
- `airport_alerts_sent.post_id` всегда равен id поста **введения**: для снятия
  туда кладётся `episode`, а не id поста-снятия. Так проверка «был ли пуш по
  эпизоду» — один `SELECT`.
- Индекс: `CREATE INDEX IF NOT EXISTS idx_subs_airports ON subscriptions(active,
  origin_iata, dest_iata)`.

## Архитектура

Новый модуль `flight_bot/airport_alerts.py`:

- `AIRPORTS` — шесть записей: IATA, русское название, regex-варианты
  (`ВНУКОВО`, `ДОМОДЕДОВО`, `ШЕРЕМЕТЬЕВО`, `ЖУКОВСКИЙ|РАМЕНСКОЕ`,
  `ПУЛКОВО`, `СОЧИ|АДЛЕР`);
- `parse_page(html) -> list[Post]` — id, время, свой текст (`js-message_text`),
  `reply_to`;
- `parse_post(post) -> list[Event]` — шаблон, режим, аэропорты;
- `Watcher` — тик: две страницы → новые/изменённые посты → события → переходы
  состояния → выборка подписчиков → тексты → `send`.

Поток:

```
main.run
  ├─ poller.run(conn, settings, send)          # как сейчас
  └─ airport_alerts.run(conn, settings, send)  # новый тик 120 с
        ├─ GET t.me/s/favt_info (+ ?before=<min>)
        ├─ parse_page → parse_post → airport_events
        ├─ airport_state: closed/partial/lifted
        ├─ SELECT active-подписки по origin_iata/dest_iata
        ├─ окно / сторона / ночь / дедуп
        └─ send(chat_id, текст) + airport_alerts_sent
```

Конфиг (`.env`):

```
AIRPORT_ALERTS=1          # 0 — выключить (обкатка/откат)
AIRPORT_ALERTS_INTERVAL_SEC=120
AIRPORT_ALERT_WINDOW_H=12
AIRPORT_ALERT_QUIET_FROM=23
AIRPORT_ALERT_QUIET_TO=7
AIRPORT_ALERT_QUIET_NEAR_H=6
```

`AIRPORT_ALERTS=0` — наблюдатель не стартует (для обкатки и отката).

## Ошибки

- **Источник недоступен.** Три неудачных тика подряд — `log.error`; тик
  продолжается, курсор не сдвигается. При восстановлении обрабатываются
  пропущенные посты, но пуши только по свежим (≤30 мин).
- **Формат канала изменился.** Если за тик распознано 0 шаблонных постов при
  непустой ленте — `log.warning` с числом постов; события не выдумываются.
- **Ошибка отправки.** Сообщение не помечается отправленным; повтор на следующем
  тике (идемпотентно по ключу дедупа).
- **Нет снимка подписки.** Пропускаем до первого опроса поллера (минуты).

## Тесты

Фикстуры (реальные посты, обезличенные по id):

1. одиночное «ВВЕДЕНЫ»;
2. список из нескольких аэропортов;
3. «по согласованию»;
4. reply-«СНЯТЫ»;
5. `UPD`-снятие в том же посте;
6. сводка оперштаба — игнорируется;
7. дубль «ВВЕДЕНЫ» — одно событие.

Юнит-тесты:

- парсер: id/время/текст/reply, шаблон, режим, аэропорты;
- переходы: closed → lifted, partial → closed, повтор, lift без open;
- окно: за 13 ч — тишина, за 11 ч — пуш; сторона: после вылета origin молчит;
- ночь: 02:00 и рейс через 10 ч — suppressed; через 3 ч — пуш;
- дедуп: один и тот же эпизод не дублируется;
- выборка подписчиков по IATA.

## Вне скоупа

- иностранные аэропорты и NOTAM-окна (юг, плановые закрытия);
- строка об аэропорте в карточке подписки (можно добавить позже);
- прямой доступ к MAX и MTProto;
- статистика/аналитика по ограничениям.

## Откат

`AIRPORT_ALERTS=0` и рестарт. Данные в SQLite остаются, на работу поллера не
влияют.

## Обоснование окна и объёма

По ленте за 36 дней (13.10–19.11.2026): 797 постов, 226 по шести аэропортам,
68% полных закрытий — ночью. У DME/VKO преобладает «по согласованию» (29 из 33–34
эпизодов), у AER — полное закрытие (13 из 13). Поэтому: оба режима, разные тексты,
тихие часы и окно 12 ч.
