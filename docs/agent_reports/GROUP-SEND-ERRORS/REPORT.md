# GROUP-SEND-ERRORS — ошибки отправки пуша и темы форума

Статус: **ПРИНЯТО** (14.10.2026 МСК). В `main` (`661d006`), запушено. На прод не выкачено.

## Проблема

`send` в `main.py` глотал любое исключение `send_message` и писал лог; подписка
оставалась `active=1` и падала на каждом пуше. С ботом в группах:

1. бота выгнали / заблокировали в личке — `TelegramForbiddenError`;
2. чата нет — `TelegramBadRequest` «chat not found»;
3. группа стала супергруппой — `TelegramMigrateToChat` с новым `chat_id`;
4. подписка из темы форума слала пуши в General: `message_thread_id` не хранился.

## Решения (согласованы с владельцем в чате)

| | Решение |
|---|---|
| (1), (2) | `storage.deactivate_chat` — снять все подписки чата; `warning` в лог с числом строк |
| (3) | `storage.migrate_chat` — перенести только живые подписки; при конфликте `UNIQUE(chat_id, flight, date)` оживить строку в новом чате, старую погасить (без дублей); пуш повторяется в новый `chat_id` |
| (4) | колонка `thread_id` (NULL — General/обычный чат, доливается `ALTER`'ом); берётся из `cb.message` только при `is_topic_message`; повторная подписка из другой темы переносит пуши туда; «message thread not found» — `storage.clear_thread` и пуш в General |
| прочее | любые другие ошибки — как раньше, только `log.exception`, подписки не трогаются |

`send` вынесен в `main.make_send(tg, conn)` — тестируется фейковым `Bot` с настоящими
исключениями aiogram 3.31.

Отвергнуто:
- хендлер служебного `migrate_to_chat_id` в `bot.py` — перенос при первом пуше достаточен;
- ограничитель рекурсии миграции — Telegram не мигрирует супергруппу повторно;
- дубль пуша в тик миграции (строки взяты снимком `due()`) — максимум один раз на группу;
- закрытая тема (`TOPIC_CLOSED`) и `TelegramRetryAfter` — только лог: слать в General
  при закрытой людьми теме навязчиво, до флуд-лимита на наших объёмах не дойти.
