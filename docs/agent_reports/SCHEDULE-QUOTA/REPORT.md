# SCHEDULE-QUOTA — защита квоты AeroDataBox

Статус: **ПРИНЯТО** владельцем 14.10.2026 МСК — [ADR-0001](../../adr/0001-aerodatabox-quota.md).
Ветка `fix/schedule-quota` от `feature/schedule-5days` (1f3b8b5) влита в `main` слиянием e7095a7
(конфликты в CHANGELOG и main.py — с OWNER_IDS из main); origin/main 661d006: 134 passed.

## Проблема (ревью feature/schedule-5days)

`registry.schedule()` зовёт AeroDataBox (6 единиц из 400/мес, т. е. ≈66 запросов)
при каждом поиске рейса:

1. ошибки не кэшировались — при 429/таймауте каждый поиск ждал до 20 с;
2. нет дедупликации — одновременные поиски одного номера = несколько платных запросов;
3. `_schedule_cache` рос без границы;
4. бот открыт всем, `FLIGHT_RE` пропускает ≈14 млн строк — перебор номеров выжигал квоту.

## Решения (согласованы с владельцем в чате)

| | Решение |
|---|---|
| (1) | ошибка → `[]` в кэше на `SCHEDULE_FAIL_TTL_SEC` = 600 с |
| (2) | `_schedule_inflight`: одна задача на номер, ждущие через `asyncio.shield`; снятие — done-callback |
| (3) | кэш хранит момент протухания; при записи удаляются протухшие, сверх `SCHEDULE_CACHE_MAX` = 1000 — самые старые; `scheduled()` протухшее не отдаёт |
| (4) | вариант B: `AERODATABOX_BUDGET` = 60 попыток за **скользящие 31 день** (любой цикл RapidAPI ≤ 60, дата сброса не нужна); счётчик — таблица `schedule_calls` в SQLite; списывается любая попытка, включая ошибки; сверх бюджета, без базы или при ошибке базы — только табло, пользователю без пометки |

Отвергнуто для (4): лимит на `chat_id` (A), расписание по кнопке (C), пауза на 429 (D);
календарный месяц МСК — до 120 запросов за один цикл RapidAPI, если тот сбрасывается не 1-го.

## Доказательства

- pytest: до правок 109 passed → 118 passed; каждый новый тест сначала падал по своей причине
  (2 вызова вместо 1; 3 вместо 1; нет `SCHEDULE_CACHE_MAX`; нет таблицы/функции бюджета;
  `CancelledError` на повторном поиске; `ProgrammingError` из закрытой базы).
- Мутация: без `asyncio.shield` тест одновременных поисков падает с `CancelledError`.
- Ревьюер на `7349775`: SHIP WITH FIXES, исправлено в `4a44709`.
- Ревьюер на `31dfb07`+`4a44709`: SHIP WITH FIXES, исправлено в `9efc2af`. Обойти бюджет он не смог:
  гонки, два процесса на одной базе, граница окна, миграция старой базы.
- Ревью `9efc2af` не проводилось.

## Не сделано / открыто

- Не знаем, тарифицирует ли RapidAPI ответы 4xx/5xx/429 — поэтому списываем любую попытку.
- Отказ по бюджету не кэшируется: на каждом поиске синхронный `DELETE/COUNT` в SQLite и warning в лог.
- Done-callback снимает запись без проверки, что это та же задача; при текущей логике это безопасно.
- Окно бюджета считается по `time.time()`: если перевести часы назад, старые записи дольше остаются в окне.
- Линтер не прогнан: в проекте нет конфига, `pyflakes` не установлен.
- Выкат на прод не делался — по команде владельца. Таблица `schedule_calls` в живой базе создаётся сама
  (`CREATE TABLE IF NOT EXISTS`), в `.env` ничего добавлять не обязательно.
