# ADR-0006. Табло SVO — домен svo.su, источники проходят редиректы

Статус: **ПРИНЯТО** 27.10.2026 МСК (владелец). Код в `main`: ff7687a (PR #12), 8a3df29 (PR #13, тест).

## Контекст

Шереметьево перенесло табло: `https://www.svo.aero/bitrix/timetable/` отвечает 301 →
`https://svo.su/bitrix/timetable/` → 301 → `https://svo.su/timetable/`. httpx по умолчанию по редиректам
не ходит, `raise_for_status` на 3xx — ошибка: каждый запрос к SVO падал (проверено 27.10 с сервера —
SU2128, SU1122, GF13 × 2 направления, 6/6). Мониторинг (ADR-0004) не предупредил: SVO опрашивается редко,
порог 6 ошибок за 30 мин не набрался.

## Решение

- `SvoSource`: адрес `https://svo.su/timetable/`, ответ — тот же JSON (поля `co`, `flt`, `dat`,
  `mar1…5`, `term`, `gate_id`, `t_st/t_et`); `follow_redirects=True` — следующий переезд не роняет источник.
- Имя источника `svo.aero` не меняем: оно записано в подписках (`source`) и задаёт порядок опроса.
- Тест `test_watchdog` починен для macOS (сокет по относительному имени: путь AF_UNIX ≤ ~104 байт).

## Что отвергли

- Переименовать источник в `svo.su` — у действующих подписок сбился бы приоритет опроса.
- Включить редиректы глобально во всех клиентах — у других источников переезда нет, редирект там может
  означать страницу-заглушку (вход, капча), а не данные.
