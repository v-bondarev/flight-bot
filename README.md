# flight-bot

Telegram-бот подписки на статус авиарейсов. На вход — номер рейса, спрашивает
дату, дальше шлёт все изменения (задержка, смена терминала/выхода, вылет,
прилёт, отмена) до завершения рейса.

## Данные (РФ): бесплатно, платное — план B

По РФ глобальные ADS-B-трекеры (FR24/OpenSky/FlightAware) над страной рваные —
основа не они, а **расписательно-статусные данные аэропортов**.

| Источник | Статус | Как |
|---|---|---|
| **SVO** (Шереметьево) | ✅ готов | Bitrix-JSON табло `www.svo.aero/bitrix/timetable/?search=<no>&direction=<dir>` — ключ не нужен |
| **DME** (Домодедово) | ✅ готов | поиск по номеру `www.dme.ru/book/live-board/?searchText=…&direction=D\|A` + `Detailed?id=`. Даёт план/факт, статус, зону (как терминал), тип ВС; **не даёт** IATA (только город), стоек, выхода, посадки, ленты. С зарубежного адреса сервера бота хост не отвечает → транспорт уходит в **scrape.do** (`geoCode=ru`) |
| **LED** (Пулково) | ✅ готов | **JSON-API** `pulkovoairport.ru/api/?type=departure\|arrival&when=-1\|0\|1&search=<цифры>` — самый полный источник: план/оценка/факт, стойки и окно регистрации, выход, посадка (план/факт), терминал, IATA и город, промежуточная точка, кодшер, лента багажа на прилёте. `search` — подстрока по цифрам, код авиакомпании сверяем сами. С сервера бота доступен напрямую |
| **VKO** (Внуково) | ❌ пока нет | табло `/ru/for-passengers/reysi/online-tablo/` за JS-челленджем антибота (счёт хэша в браузере, куки, reload) — стоит и для РФ-адресов. Эмулировать челлендж в коде не делаем (обход бот-детекции); честный путь — браузерный рендер: scrape.do `render=true&customWait` проходит, но нестабилен (502). Пока VKO-рейсы идут через AirLabs |
| Прочие РФ (антибот/JS) | ⏳ | тот же `Fetcher`: напрямую, при блоке — scrape.do |
| **AirLabs** (airlabs.co) | ✅ готов | резолвер «номер→аэропорт» и статус вне наших табло (им же пользуется Flighty). Проверено с сервера: знает и SU2128 (времена сходятся с табло до минуты), и внутренний S7 2050 DME→Сочи. Городов не отдаёт, плиток стоек/выхода нет — фолбэк |
| Yandex Расписания | 💤 | бесплатный ключ — резерв реестра, обяз. атрибуция |
| AeroDataBox | 💤 план B | платно (~$5/мес), тем же контрактом |

Flighty (flighty-mcp) в расчёт не берём: он читает локальную базу macOS-приложения,
на сервере это не источник.

## Архитектура

Плагинная, бизнес-логика не знает происхождения данных:

- `FlightSource` — источник статуса по номеру+дате → `list[FlightSnapshot]`
  (реализовано: `SvoSource`).
- `AirportResolver` — «номер рейса → аэропорт(ы)» (`FlightRoute`), чтобы понять,
  чьё табло опрашивать. Для Москвы роль резолвера играет опрос настроенных
  табло (они сами по номеру отдают маршрут); для остального мира — Yandex
  (бесплатно) или AeroDataBox (план B).
- `FlightSnapshot` — нормализованный снимок; diff двух снимков = список изменений.
- `http.Fetcher` — один транспорт для табло, три ступени: **напрямую → свой
  RU-прокси → scrape.do**. Свой прокси — SSH-туннель с SOCKS до хоста с российским адресом
  (`RU_PROXY_URL`, юнит `deploy/ru-proxy.service`; на RU-хосте ничего не
  ставится, прокси делает sshd), scrape.do (`geoCode=ru`) — платный резерв.
  Провал ступени запоминается на процесс, чтобы не платить таймаутом каждый
  опрос; последняя ступень пробуется всегда. Факт: часть табло не отвечает
  с зарубежного адреса сервера бота, с российского — отвечает.
- Подписка хранит **источник**, где рейс нашли, и опрашивается им первым;
  остальные — только если он рейс потерял. Иначе с ростом числа табло каждый
  опрос ходил бы по всем подряд.

## Другие аэропорты: РФ и не-РФ

- **РФ.** Единого API нет, у каждого аэропорта своё табло, универсального
  HTML-парсера не бывает. Модель — **по плагину на аэропорт**, добавляемому по
  потребности: класс `FlightSource` (~100 строк) + боевая фикстура + тест,
  одна строка в `registry.SOURCES`. Очередь: VKO → LED → далее по спросу.
  Если табло с антиботом/JS или гео-блоком — `Fetcher` уводит в scrape.do.
- **Не-РФ.** Свои парсеры не пишем: универсальный слой — **AirLabs**
  (маршрут, статус, гейт/терминал), за полнотой (хронология, оценки) —
  **AeroDataBox** (план B, платно), тем же контрактом.
- Каскад всегда *табло → AirLabs → (AeroDataBox)*: AirLabs не всеведущ
  (GF013 он не знает), табло — первоисточник.

```
номер рейса ──> AirportResolver ──> аэропорт(ы) ──> FlightSource(табло) ──> FlightSnapshot
                                                                              │
                              подписка ── опрос по расписанию ── diff ────────┘──> пуш в Telegram
```

## Как работает бот

1. Пользователь шлёт номер рейса (`SU2128`) → бот пробует его на настроенных
   табло в обоих направлениях (`registry.probe`) и показывает найденные даты
   кнопками.
2. Тап по дате → подписка в SQLite + карточка текущего статуса.
3. Поллер снимает снапшот каждой активной подписки, считает
   `diff_snapshots(prev, curr)` и шлёт **только изменения**, по хронологии
   страницы: регистрация открыта/закрыта → посадка → вылет → прилёт, плюс
   выход, терминал, лента багажа, отмена. Сдвиг времени — от 5 минут: табло
   дёргает оценку на минуту-две, «мелкий сдвиг пугать незачем».
4. Частота опроса адаптивная: раз в час, пока до вылета >6 ч; раз в
   `POLL_INTERVAL_SEC` (5 мин) в окне у вылета и в воздухе; раз в 2 мин с
   начала посадки.
5. Подписка снимается сама: после прилёта, при отмене и через сутки после
   даты рейса, если он так и не появился на табло.

Диффер считает по структурным полям (появление факта), а не по сырому тексту
статуса табло — тот шумный. Единственное текстовое событие — отмена.

## Формат сообщений

Эталон — страница flight.vbondarev.ru (`site/flight/index.html`): её раскладка
и тексты перенесены один в один и закреплены тестами (`tests/test_render.py`).

Карточка при подписке:

```
GF013 · Gulf Air · Airbus A321neo
📅 6 сентября
🛫 SVO Москва → BAH Бахрейн       ← конечная точка, не ближайшая посадка
↪️ через TBS Тбилиси              ← только у рейсов с промежуточной посадкой
🕒 Вылет 10:45 · Прилёт 19:35     ← при сдвиге: ~~10:45~~ 11:30

⚪ Регистрация в 07:45            ← 🟡 задержка, 🔵 идёт/в воздухе, 🟢 прилетел, 🔴 отменён
⏳ До регистрации 12 ч 50 мин     ← обратный отсчёт, как на странице

🛎 Стойки — · откроется в 07:45
🚪 Выход 146 · посадка за 40 мин до вылета
🏢 Терминал C

📋 Хронология
🛎 Регистрация · 07:45
🔒 Регистрация закрыта · 09:45
🚶 Посадка · ждём табло
✈️ Вылет · 10:45
🛬 Прилёт · 19:35
```

Иконки — те же, что у событий в пуше: один язык на карточку и уведомления.
Для прилёта — свои плитки (🧳 лента багажа, 🚪 гейт прилёта) и два шага.
Пуш — только дельта: `🔔 GF013 · SVO→BAH · 06.09` и строки изменений.
В кнопках дат прошедшие дни не предлагаются.

## Разработка

```bash
pip install -r requirements.txt pytest
pytest
```

Тесты не ходят в сеть: парсер SVO гоняется на боевой фикстуре, поллер — с
подменённым источником.

## Деплой

Сервер бота, каталог `/opt/flight-bot` — отдельно от сайта,
доставка через `git push`/`git pull`. Секреты — в `/opt/flight-bot/.env`
(см. `.env.example`, в git не коммитится).

```bash
cd /opt/flight-bot && git pull
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
sudo cp deploy/flight-bot.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now flight-bot
```

Обновление: `git pull && sudo systemctl restart flight-bot`.
